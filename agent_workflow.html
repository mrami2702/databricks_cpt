Example Query — Geospatial Data Discovery

User Query "Hey, I have data in the dev_europa.gold_roses schema — it has mineral sample data with element concentrations, coordinates, and depth measurements. Can you find me external datasets that are similar or could add value to what I have? My data is a bit sparse and I need more on these minerals."
1
RootAgent — receives query
Identifies this as a data discovery request referencing an internal Databricks schema. Decides on a two-step chain: first understand the internal data, then search for external matches.
→ routes to DatabricksCatalogAgent → then EDXDataDiscoveryAgent
2
DatabricksCatalogAgent — inspects the schema
Explores the dev_europa.gold_roses schema to understand what data exists — column names, data types, geographic extent, and sample values.
describe_table get_dataset_schema preview_data profile_dataset
Returns to RootAgent ↓
32 tables found. Key columns: element_name, concentration_ppm, latitude, longitude, depth_m, sample_id, rock_type. Mineral types include silica, calcite, iron oxide, rare earth elements. Location: ~47°N, 108°W (Wyoming region). Numeric columns sparse — avg 23% null rate on concentration fields.
3
RootAgent — builds context for EDX
Packages schema findings into a search context: minerals (silica, iron oxide, REE), location (Wyoming), key variables (concentration, depth, rock type), format need (CSV for joining), and geospatial requirement (coordinates must be present).
→ routes to EDXDataDiscoveryAgent with context
4
EDXDataDiscoveryAgent — discovers matching external datasets
Runs a sequence of targeted searches against the NETL EDX CKAN API using the schema context. Starts by discovering EDX vocabulary, then searches with combined criteria, then drills into the best candidates.
Tool call sequence
list_edx_tags() → discover EDX vocabulary
Finds exact EDX tag names for the domain: "Rare Earth Elements", "Geochemistry", "Wyoming", "Well logs", "Mineralization" — avoids term mismatch in subsequent searches.
search_edx_multi_criteria(["rare earth elements", "Wyoming", "geochemical"], require_geospatial=True)
AND-search for all three criteria. Returns only datasets matching all of them AND flagged geospatial.
search_edx_by_format("CSV", query="mineral concentration")
Finds CSV-format datasets that can be joined directly to the Databricks table on coordinates or sample_id.
find_edx_datasets_like(["Rare Earth Elements", "Mineralization", "Wyoming"])
Tag-overlap similarity search — finds datasets sharing the most tags with the user's domain. Ranked by overlap count.
get_edx_dataset_details("top-candidate-name") × top 3–5 candidates
Retrieves full metadata + resource list with direct download URLs for the most promising datasets.
Returns to RootAgent ↓
5 ranked external datasets with geospatial relevance, download links, file formats, and suggested join strategy for each.
5
RootAgent — synthesizes final answer
Merges the schema understanding from DatabricksCatalogAgent with the EDX discovery results from EDXDataDiscoveryAgent into a cohesive, human-readable response. Translates raw JSON into enrichment recommendations.
6
Final Response → User
The user receives a structured enrichment report — no raw JSON, no tool output — just actionable recommendations:
Sample Output Your gold_roses schema has 32 tables with mineral concentration data (lat/lon coordinates) — concentration fields are ~23% sparse, so enrichment makes sense. Here are 5 external datasets from NETL EDX that can add value:

1. Wyoming REE Geochemical Survey (CSV, 2021) — Covers the same ~47°N region. Join on coordinates (±0.01°). Adds: rare earth concentrations, rock type classifications. ↗ edx.netl.doe.gov/dataset/ree-wyoming-survey

2. National Mineral Database — Western Basins (Shapefile) — Bounding box overlaps with your data. Adds: formation names, deposit types, mineralization grades. Join on latitude/longitude.

+ 3 more datasets with similarity explanations and download links…
